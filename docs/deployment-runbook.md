# Veridoc — Deployment Runbook

> *Pick one platform from the options below. Render is recommended for the simplest free-tier setup.*

---

## Option A: Render (Recommended — easiest free tier)

### Prerequisites
1. [Render account](https://render.com) (free tier: 512MB RAM per service)
2. [GitHub account](https://github.com) connected to Render

### ⚠️ Security: Secrets Required

`docker-compose.yml` now uses `${JWT_SECRET:?error}` and `${FILE_ENCRYPTION_KEY:?error}` syntax —
the stack **will refuse to start** without these variables set. This is intentional.

Generate them before deploying:
```bash
python -c "import secrets; print(secrets.token_hex(32))"  # JWT_SECRET
python -c "import base64, os; print(base64.urlsafe_b64encode(os.urandom(32)).decode())"  # FILE_ENCRYPTION_KEY
```

### Steps

```bash
# 1. Push the repository to GitHub
git remote add origin https://github.com/YOUR_USERNAME/veridoc.git
git push -u origin main

# 2. In Render Dashboard → New → Blueprint
# Connect your GitHub repository
# Render will auto-detect render.yaml (create it first)

# 3. Set environment variables in Render dashboard:
#    ⚠️ REQUIRED:
#    JWT_SECRET=<run generation command above>
#    FILE_ENCRYPTION_KEY=<run generation command above>
#    ⚠️ ALSO REQUIRED:
#    POSTGRES_PASSWORD=<auto-generated by Render>
#    MINIO_ACCESS_KEY=<generate a random string>
#    MINIO_SECRET_KEY=<generate a random string>

# 4. Deploy
# Render will build and deploy all services

# 5. Verify
curl https://<your-app>.onrender.com/api/v1/health
```

### render.yaml (place in repo root)

```yaml
services:
  - type: web
    name: veridoc-backend
    env: docker
    dockerfilePath: ./backend/Dockerfile
    envVars:
      - key: APP_ENV
        value: production
      - key: JWT_SECRET
        sync: false  # Set manually in dashboard
      - key: FILE_ENCRYPTION_KEY
        sync: false
      - key: POSTGRES_HOST
        fromService:
          type: postgres
          name: veridoc-db
          property: host
      - key: POSTGRES_PASSWORD
        fromService:
          type: postgres
          name: veridoc-db
          property: password

  - type: web
    name: veridoc-frontend
    env: docker
    dockerfilePath: ./frontend/Dockerfile
    envVars:
      - key: NEXT_PUBLIC_API_URL
        fromService:
          type: web
          name: veridoc-backend
          property: host

  - type: postgres
    name: veridoc-db
    plan: free
```

## Option B: Fly.io

```bash
# 1. Install flyctl
curl -L https://fly.io/install.sh | sh

# 2. Login
fly auth login

# 3. Launch (follow prompts)
fly launch

# 4. Set secrets
fly secrets set JWT_SECRET=<generated> \
                FILE_ENCRYPTION_KEY=<generated> \
                POSTGRES_PASSWORD=<generated>

# 5. Create Postgres
fly postgres create --name veridoc-db
fly postgres attach veridoc-db

# 6. Deploy
fly deploy
```

### fly.toml (auto-generated, then customize)

```toml
[build]
  dockerfile = "backend/Dockerfile"

[env]
  APP_ENV = "production"

[[services]]
  http_checks = []
  internal_port = 8000
  protocol = "tcp"
  script_checks = []
  [services.concurrency]
    type = "connections"
    hard_limit = 25
    soft_limit = 20
```

## Option C: Vercel (Frontend) + Railway (Backend + Postgres)

### Frontend → Vercel
```bash
# 1. Install Vercel CLI
npm i -g vercel

# 2. Deploy frontend
cd frontend
vercel --prod

# 3. Set environment variable
vercel env add NEXT_PUBLIC_API_URL https://<backend>.railway.app
```

### Backend → Railway
```bash
# 1. Push backend to Railway
#    Use Railway dashboard → New Project → Deploy from GitHub repo

# 2. Add Postgres plugin in Railway dashboard

# 3. Set environment variables in Railway dashboard
```

## Post-Deployment Verification

```bash
# 1. Check health endpoint
curl https://<your-url>/api/v1/health
# Expected: {"status":"ok","dependencies":{"postgres":{"status":"ok"},...}}

# 2. Register a test user
curl -X POST https://<your-url>/api/v1/auth/register \
  -H "Content-Type: application/json" \
  -d '{"email":"test@example.com","password":"TestPass123!","full_name":"Test User"}'

# 3. Upload a test document
curl -X POST https://<your-url>/api/v1/documents/upload \
  -H "Authorization: Bearer <token>" \
  -F "file=@data/documents/synthetic_contract.txt"

# 4. Create a conversation and ask a question
curl -X POST https://<your-url>/api/v1/chat/stream \
  -H "Authorization: Bearer <token>" \
  -H "Content-Type: application/json" \
  -d '{"conversation_id":"<id>","message":"What is this document about?"}'
```

## Cost Estimate (Free Tier)

| Service | Render Free | Fly.io Free | Railway Free |
|---------|-------------|-------------|--------------|
| Backend | 512MB RAM (sleeps after 15min idle) | 256MB RAM (always-on limited) | 512MB RAM ($5 credit/mo) |
| Frontend | Static site (sleeps with backend) | Included in app | Included |
| Postgres | 256MB disk (free) | 1GB disk (free) | $5 credit covers |
| Total | **$0/mo** (cold-start on first request) | **$0/mo** (limited always-on hours) | **$0/mo** (if within credits) |

**Recommendation:** Use Render free tier. The only trade-off is a ~30s cold-start on the first request after inactivity. For a demo portfolio site, this is acceptable. After proving interest, upgrade to Render's $7/mo starter plan for always-on.
